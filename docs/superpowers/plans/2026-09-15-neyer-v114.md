# Neyer Gap Test V1.14 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and release a standalone V1.14 that correctly reports gap probabilities and supports an honest first-study workflow when variation is unknown.

**Architecture:** Keep readable MATLAB functions in `application/source/`, add small focused helpers for study mode and automatic search scale, and assemble them into one self-contained Live Script. Preserve V1.13 byte-for-byte, remove planner/R-C entry points only from the V1.14 menu and direct workflow, and verify both source and embedded Live Script with path-isolated tests.

**Tech Stack:** MATLAB R2022b, `matlab.unittest`, MATLAB Live Editor conversion APIs, PowerShell standalone assembler, Git.

**Spec:** `docs/superpowers/specs/2026-09-15-neyer-v114-design.md`

## Global Constraints

- `delivery/Neyer_Gap_Test_v1_13.m` and `delivery/Neyer_Gap_Test_v1_13.mlx` must remain byte-for-byte unchanged.
- The final deliverable must be one standalone MATLAB `.mlx` with no required outside files.
- Supported MATLAB version is R2022b.
- Smaller gap means Interaction is more likely; larger gap means No interaction is more likely.
- Requested gaps display with two decimal places and come only from the selected reachable-gap model.
- Each newly built setup uses one measured gap reading, and that measured value enters the fit.
- Do not build or expose the fixed-gap R/C qualification calculator in V1.14.
- Use jargon-free labels, explanations, and errors.
- Do not silently overwrite saved results.
- Store evidence under `audit/v114/` and final files under `delivery/` before copying verified artifacts to OneDrive.
